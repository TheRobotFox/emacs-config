This is the source for =init.el= and =early-init.el=. After editing, run
=org-babel-tangle= (=C-c C-v t=), then restart Emacs to check startup.
The files in =lisp/= are handwritten helpers and are loaded by this configuration.
Run the focused regression checks with:
=emacs -Q --batch -l tests/config-tests.el -f ert-run-tests-batch-and-exit=.

Keep package settings, hooks, and bindings together. Put shared editing commands
in =lisp/= and document their purpose here. The final =COMMENT Experiments=
subtree is inactive. To enable an experiment, move it to its owning section
and remove any explicit =:tangle no= header.

Intentional settings belong here. =custom.el= holds Custom's local bookkeeping
(such as trusted themes), and is optional on a fresh checkout.

** Popper

*** Supporting panes and navigation

With one editing column and at least 140 columns of frame width, supporting panes
open on the right: documentation above, shell/REPL/output below. Otherwise they
open at the bottom, with documentation on the left and process output on the right.
Existing panes stay in place until closed or moved with =M-o s=; visible buffers reuse their windows.

| Key | Action |
|-----+--------|
| =M-o e= | Select this project's Eshell; create it on first use |
| =M-o r= | Select the associated language REPL or choose a project REPL |
| =M-o d= | Toggle full Eldoc without leaving your code |
| =M-o s= | Switch open supporting panes between right and bottom, keeping focus |
| =C-c o= | Toggle the latest popup |
| =C-c O= | Cycle popups using Popper's normal order |
| =C-c M-o= | Promote a popup to an ordinary buffer, or demote it |

Eshell and REPL commands select the process pane; Popper toggles individual popups.
Start Python, SLY, and Haskell runtimes with their normal commands first.
Popups use the source project as their group, or its directory outside a project.

Eldoc shows short documentation in the echo area and full documentation in its pane.
In Dired, clicks and =RET= open in place; =o= opens another window and =C-o= previews.

Load the supporting-pane display action and expose direct commands under one prefix.
Make Dired mouse clicks match keyboard navigation.
#+begin_src emacs-lisp

  "e" #'my/popup-eshell
  "r" #'my/popup-repl
  "d" #'my/popup-eldoc
  "s" #'my/popup-toggle-side)
(keymap-global-set "M-o" my/popup-command-map)
(with-eval-after-load 'dired
  (keymap-set dired-mode-map "<mouse-2>" #'dired-mouse-find-file))
(setopt eldoc-echo-area-use-multiline-p nil
        eldoc-echo-area-prefer-doc-buffer t)

Display C++ reference entries using the external =cppman= and =col= commands.

(defun my/cppman (entry)
  "View C++ reference entry using cppman in Emacs, similar to man command.
If called interactively with no argument, uses the symbol at point as default."
  (interactive
   (list (let* ((default (thing-at-point 'symbol t))
                (prompt (if default
                            (format "C++ Reference entry (default %s): " default)
                          "C++ Reference entry: ")))
           (read-string prompt nil nil default))))
  (let ((buffer (get-buffer-create (format "*cppman %s*" entry))))
    (with-current-buffer buffer
      (setq buffer-read-only nil)
      (erase-buffer)
      (call-process-shell-command
       (format "cppman %s | col -b" (shell-quote-argument entry))
       nil (current-buffer))
      (if (zerop (buffer-size))
          (message "No results found for %s" entry)
        (special-mode))
      (setq buffer-read-only t)
      (beginning-of-buffer))
    (unless (zerop (buffer-size))
      (switch-to-buffer buffer))))

**** Source/header creation

Create a companion implementation file from a C/C++ header.
For C++ headers, carry the enclosing namespace into the generated file.
#+begin_src emacs-lisp
(defun my/create-src-file ()
  "Create a new implementation buffer for the current C or C++ header."
  (interactive)
  (unless buffer-file-name
    (user-error "This buffer does not visit a file"))
  (let* ((file buffer-file-name)
         (ext (file-name-extension file))
         (new-ext (pcase ext ("h" "c") ("hpp" "cpp")
                         (_ (user-error "Expected a .h or .hpp header"))))
         (target (file-name-with-extension file new-ext))
         namespaces)
    (when (or (file-exists-p target) (get-file-buffer target))
      (user-error "Implementation file or buffer already exists: %s" target))
    ;; Inspect the header before switching buffers.  Plain C needs no parser.
    (when (equal ext "hpp")
      (unless (treesit-parser-list)
        (user-error "C++ namespace detection requires a Tree-sitter parser"))
      (let ((node (treesit-node-at (point))))
        (while node
          (when (equal (treesit-node-type node) "namespace_definition")
            (when-let* ((name (treesit-node-child-by-field-name node "name")))
              (push (treesit-node-text name t) namespaces)))
          (setq node (treesit-node-parent node)))))
    (let* ((namespace (string-join namespaces "::"))
           (contents (concat "#include \"" (file-name-nondirectory file) "\"\n\n"
                             (unless (string-empty-p namespace)
                               (format "namespace %s {\n} // %s" namespace namespace)))))
      (find-file-other-window target)
      (atomic-change-group (insert contents)))))
#+end_src

** Tasks, agenda, and capture

*** Everyday workflow

Project tasks live in =task.org= at the repository root; general tasks can stay
in any Roam node or in =inbox.org= under the Roam directory. No date is required.

| Key | Action |
|-----+--------|
| =C-x p C= | Explicit project task capture; select a project when outside one |
| =C-c n t= | Task in current or selected Roam node, regardless of project context |
| =C-c n c i= | General inbox task, from anywhere |
| =C-c n c p= | Project TODO; shown only when a project is available |
| =C-c a= | Standard Org agenda menu |
| =C-c a o= | Overview: week and all open tasks across projects, Roam, and legacy files |
| =C-c a f= | Focus: today's agenda and NEXT actions, sorted by category |
| =C-c a r= | Review: inbox, undecided TODOs, and waiting or deferred work |
| =C-c a p= | Current or selected project's overview |
| =C-x p a= | Current or selected project's overview |
| =C-x p t= | Open the project's task file |
| =C-x p n= | Open or create the project's Roam note |
| =C-c n P= | Associate an existing Roam note with a project |

Finish capture with =C-c C-c=, or cancel with =C-c C-k=. In an overview, =g=
discovers new task sources and refreshes the view; =RET= visits the task.
Use =NEXT= for actionable work and =WAIT= for dependencies; unscheduled TODOs
remain visible. In the agenda menu, =a= shows just the calendar and =t= just TODOs.

During a review, process the inbox and choose a few =NEXT= actions; check =WAIT=
for follow-ups and keep deferred work in =HOLD=, =IDEA=, or =DISSOLVE=.
Schedule work when you intend to start it; use deadlines for real due dates.
Focus shows every =NEXT= action, including unscheduled ones. The full overview
remains the inventory of all open work, and the project view separates states.

In an agenda, =TAB= previews the source, =t= changes state, =C-c C-s= schedules,
and =C-c C-d= sets a deadline. Use =/= to filter, or =m= then =B= for bulk actions.

A project note's file-level =PROJECT_ROOT= property gives project.el repository
context. Capture can target the repository, current node, or inbox.
Use =C-c n T= to add Roam tags.

The overview discovers =task.org= and =tasks.org= in remembered projects and
linked project notes, plus legacy task files and Roam TODOs.
Set =my/task-extra-files= for additional sources.

  (cl-defmethod org-roam-node-doom-filetitle ((node org-roam-node))
    "Return the value of \"#+title:\" (if any) from file that NODE resides in.

    (let ((title     (org-roam-node-title node))

                   separator title))
        ;; node is a heading with an arbitrary outline path

                   separator (propertize (string-join olp separator) 'face '(shadow italic))
                   separator title)))))

** GLSL / Polymode

Retain the unused GLSL/Polymode experiment for a future workflow discussion.
Its original delimiters and broad file associations need review before activation.
#+begin_src emacs-lisp
(use-package glsl-mode)
(use-package polymode

  :config
  ;; 1. Define the GLSL inner mode chunk
  (define-innermode poly-glsl-string-innermode
                    :mode 'glsl-mode
                    ;; Adjust head-matcher regex to fit your preferred language's string style
                    ;; This looks for a magic comment like /* glsl */ followed by a quote or backtick
                    :head-matcher "\"\"\"\\W*#version "
                    :tail-matcher "\"\"\""
                    :head-mode 'host
                    :tail-mode 'host)

  ;; 2. Tie it to a host mode (e.g., C++ mode)
  (define-hostmode poly-c++-hostmode :mode 'c++-mode)
  (define-hostmode poly-haskell-hostmode :mode 'haskell-mode)

  (define-polymode poly-c++-glsl-mode
                   :hostmode 'poly-c++-hostmode
                   :innermodes '(poly-glsl-string-innermode))

  (define-polymode poly-haskell-glsl-mode
                   :hostmode 'poly-haskell-hostmode
                   :innermodes '(poly-glsl-string-innermode))

  ;; 3. Associate your files with the new polymode
  (add-to-list 'auto-mode-alist '("\\.cpp\\'" . poly-c++-glsl-mode))
  (add-to-list 'auto-mode-alist '("\\.hs\\'" . poly-haskell-glsl-mode)))
